# Build Things

Use this skill when momentum matters more than polish.

## Default approach

1. Clarify goal in one sentence.
2. Choose the smallest useful v1.
3. Build end-to-end before optimizing.
4. Validate with one fast check.
5. Document next two iterations.

## Response format

Return sections in this order:

1. **Goal**
2. **Smallest Useful v1**
3. **Implementation Plan**
4. **Build Now**
5. **Quick Validation**
6. **Next Iterations**

## Guardrails

- Prefer working output over elaborate architecture.
- Avoid adding dependencies unless they remove substantial implementation time.
- Call out assumptions clearly when requirements are incomplete.
